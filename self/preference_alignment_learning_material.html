Preference Alignment for Large Language Models

SFT, RLHF, DPO and ORPO — From Fundamentals to Practical Fine-Tuning

1. Introduction

Large Language Models can generate text, answer questions, summarize documents, write code and perform reasoning tasks. However, capability and behavior are different things.

A model may know how to answer a question but still produce an answer that is too verbose, poorly structured, insufficiently helpful, factually unreliable, incomplete, or inappropriate for the intended audience.

Core question: How do we teach an already capable language model which answers humans prefer?

This is the problem addressed by preference alignment.

Pretraining
    ↓
Supervised Fine-Tuning (SFT)
    ↓
Instruction Model
    ↓
Preference Optimization
    ↓
Evaluation
    ↓
Deployment

2. The LLM Training Lifecycle

2.1 Pretraining

During pretraining, a model learns from a huge corpus of text. For a causal language model, the basic objective is to predict the next token.

The capital of France is → Paris

The model learns language, grammar, facts, concepts, patterns, coding patterns and reasoning patterns. It does not necessarily learn to behave like a useful assistant.

2.2 Supervised Fine-Tuning

SFT provides examples of instructions and desired answers:

User:
What is photosynthesis?

Assistant:
Photosynthesis is the process by which green plants...

The model learns:

instruction → desired response

3. Supervised Fine-Tuning (SFT)

The SFT objective can be expressed as:

LSFT = − Σt log P(yt | y<t, x)

Where x is the input and y is the target response.

SFT answers:

“Given this input, what response should I generate?”

4. Why SFT Is Not Enough

Consider two possible answers:

Response A
Photosynthesis is the process by which plants convert light energy into chemical energy.
Response B
Photosynthesis is a very complicated process involving many different biological and chemical things...

Both could be valid training responses, but a human may clearly prefer A.

SFT represents:

Prompt → A

Preference learning represents:

Prompt
  ├── A  ← chosen
  └── B  ← rejected

5. What Is Preference Alignment?

Preference alignment teaches a model using comparisons between responses.

{
  "prompt": "Explain photosynthesis.",
  "chosen": "Photosynthesis is the process by which plants...",
  "rejected": "Photosynthesis is basically when plants..."
}

The essential relationship is:

chosen > rejected

The objective is to make the model prefer the chosen response relative to the rejected response.

6. RLHF — The Traditional Approach

Reinforcement Learning from Human Feedback traditionally uses several stages.

Base Model
    ↓
SFT
    ↓
SFT Model
    ↓
Generate Responses
    ↓
Human Preferences
    ↓
Reward Model
    ↓
PPO
    ↓
Aligned Model

Key components

  • Policy model: the model being optimized.
  • Reference model: a reference policy used to constrain optimization.
  • Reward model: predicts human preference.
  • PPO: reinforcement-learning algorithm used to optimize the policy.

Why is RLHF complicated?

  • Multiple models and training stages.
  • Reward-model quality affects the final result.
  • Reinforcement-learning optimization can be sensitive.
  • Generation and rollout can be computationally expensive.

7. Direct Preference Optimization (DPO)

DPO was introduced as a way to optimize a language model directly from preference data without explicitly training a separate reward model and running PPO.

Traditional RLHF:

Preference Data
      ↓
Reward Model
      ↓
PPO
      ↓
Policy

DPO:

Preference Data
      ↓
DPO Loss
      ↓
Policy

DPO intuition

Suppose the model receives a prompt and two answers. A human prefers A over B.

Prompt
  ├── Response A ← preferred
  └── Response B ← rejected

DPO increases the relative preference for A over B.

8. DPO Mathematics

A commonly used form of the DPO objective is:

LDPO(θ) = − E[ log σ( β [ log(πθ(yw|x) / πref(yw|x)) − log(πθ(yl|x) / πref(yl|x)) ] ) ]

SymbolMeaning
xPrompt
ywChosen / winning response
ylRejected / losing response
πθTrainable policy model
πrefReference model
βPreference / regularization parameter
σSigmoid function

The key idea is to compare how strongly the current model favors the chosen answer versus the rejected answer, relative to the reference model.

Why does DPO need a reference model?

The reference model acts as an anchor. It helps prevent the optimized model from moving arbitrarily far from its original behavior.

Reference Model
      │
      │ anchor
      ▼
Current Policy
      │
      ▼
Preference Update

Important DPO hyperparameters

  • β: controls the strength/scaling of the preference objective.
  • Learning rate: should be chosen carefully to avoid overfitting or unstable updates.
  • Maximum sequence length: must accommodate prompt and response content.
  • Batch size: affects optimization stability and memory.

9. Odds Ratio Preference Optimization (ORPO)

ORPO combines the supervised fine-tuning objective with a preference objective in a single training process.

SFT Loss
   +
Preference Loss
   =
ORPO Loss

A simplified representation is:

LORPO = LSFT + λ LOR

ORPO intuition

Instead of first teaching the model the task and then performing preference optimization, ORPO simultaneously learns the desired response and the preference relationship.

Prompt
  │
  ├───────────────┐
  ▼               ▼
Chosen          Rejected
  │               │
  ▼               ▼
SFT objective   Preference objective
  │               │
  └───────┬───────┘
          ▼
       ORPO Loss
          │
          ▼
       Model Update

Understanding odds

For a probability p:

Odds = p / (1 − p)

For example, if p = 0.8, the odds are 0.8 / 0.2 = 4.

11. Preference Dataset Design

Preference data quality is one of the most important factors in successful alignment.

Standard explicit preference format

{
  "prompt": "What causes leaf yellowing?",
  "chosen": "Leaf yellowing can have several causes...",
  "rejected": "It is always caused by nitrogen deficiency."
}

Conversational format

{
  "prompt": [
    {"role": "user", "content": "Explain recursion."}
  ],
  "chosen": [
    {"role": "assistant", "content": "Recursion is..."}
  ],
  "rejected": [
    {"role": "assistant", "content": "It is complicated..."}
  ]
}

What makes a good chosen response?

  • Accurate
  • Relevant
  • Complete
  • Clear
  • Actionable when appropriate
  • Well grounded in evidence
  • Appropriate for the target audience
  • Safe

What makes a poor preference dataset?

  • Incorrect chosen/rejected labels
  • Ambiguous preferences
  • Strong formatting bias
  • Length bias
  • Duplicate examples
  • Low-quality generated answers
  • Inconsistent annotation criteria

13. LoRA and QLoRA

Preference training can be memory intensive. Parameter-efficient fine-tuning reduces the number of trainable parameters.

Base Model
████████████████████  frozen

LoRA Adapter
██                  trainable

QLoRA combines low-rank adapters with quantized base-model weights to reduce memory requirements.

14. Hugging Face TRL

Hugging Face TRL provides trainers for modern post-training workflows, including SFT, DPO and ORPO.

Trainer APIs can change between releases, so the installed TRL version and its matching documentation should be treated as the implementation reference.

15. Practical Implementation

15.1 DPO

from datasets import load_dataset
from trl import DPOTrainer

dataset = load_dataset(
    "trl-lib/ultrafeedback_binarized",
    split="train"
)

trainer = DPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    train_dataset=dataset,
)

trainer.train()

15.2 DPO configuration

from trl import DPOConfig, DPOTrainer

config = DPOConfig(
    output_dir="./dpo-output",
    beta=0.1,
    learning_rate=5e-6,
    num_train_epochs=1,
    per_device_train_batch_size=2,
)

trainer = DPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    args=config,
    train_dataset=dataset,
)

trainer.train()

15.3 ORPO

from trl.experimental.orpo import ORPOTrainer
from trl.experimental.orpo import ORPOConfig

config = ORPOConfig(
    output_dir="./orpo-output",
    beta=0.1,
)

trainer = ORPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    args=config,
    train_dataset=dataset,
)

trainer.train()

Note: ORPO support and import paths may vary by TRL release. Verify the API against the version installed in your environment.

17. Common Failure Modes

17.1 Overfitting

High training preference accuracy but poor evaluation performance can indicate overfitting.

  • Dataset too small
  • Too many epochs
  • Learning rate too high
  • Noisy preferences
  • Insufficient diversity

17.2 Preference hacking

The model may learn superficial properties such as “longer is better” or “more headings is better”.

17.3 Incorrect preferences

Preference optimization amplifies the preference signal you provide. Incorrect labels can therefore produce undesirable behavior.

17.4 Capability regression

A model can improve on preference-style behavior while becoming worse on general reasoning, coding or factual tasks. Always compare against the base model.

17.5 Domain mismatch

Generic preference data may not teach the specialized behavior required by a domain-specific assistant.

20. Exercises

Exercise 1 — Which method?

You have only prompt + ideal response examples. Which method should you start with?

Answer: SFT.

Exercise 2 — Preference pairs

You have prompt + chosen + rejected. Which methods can use this data?

Answer: DPO and ORPO, among other preference-optimization methods.

Exercise 3 — DPO reference model

Why does standard DPO use a reference model?

Answer: It provides a reference policy that anchors the optimization and forms part of the DPO objective.

Exercise 4 — ORPO

What is the major architectural difference between DPO and ORPO?

Answer: DPO traditionally uses a reference model, while ORPO combines SFT and preference optimization into one objective without a separate reference model.

Exercise 5 — Bad labels

Your preference dataset contains many incorrect chosen/rejected labels. Should you increase the number of training epochs?

Answer: No. Improve the preference dataset first.

21. Final Summary

DPO

Question: Which response should the model prefer?

ORPO

Question: Can the model learn the desired response and preference simultaneously?

Pretraining
    ↓
Learn language and knowledge

SFT
    ↓
Learn the task / instruction

DPO
    ↓
Learn which behavior is preferred

ORPO
    ↓
Learn desired behavior + preference together
Most important lesson: Preference optimization does not automatically make a model truthful, knowledgeable or better. It optimizes the preference signal you provide. High-quality preference data and rigorous evaluation are therefore fundamental.
